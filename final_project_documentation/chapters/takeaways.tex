\chapter{Limitations and Future Improvements}\label{chap:limitations}

\begin{warningbox}[Current Limitations]
Our review identified a few areas that are still early or incomplete. Although we
closed the six critical QA findings during the production remediation cycle
(Section~\ref{sec:testing}), we found that regular users are still not issued a
session or token. Moreover, the \texttt{/products}, \texttt{/products/[id]},
and \texttt{/categories} pages are still placeholders
(Section~\ref{sec:frontend-completeness}), as is the admin dashboard's metrics
display. We also found that MongoDB runs without authentication or redundancy
(Section~\ref{sec:sec-data}), and \texttt{values.yaml} still carries an unused
plaintext secrets block worth cleaning up (Section~\ref{sec:sec-secrets}). In
addition, the Kubernetes API endpoint, worker SSH, and the NodePort range are currently
reachable from \texttt{0.0.0.0/0} (Section~\ref{sec:sec-network}), and the Helm
chart and raw Kubernetes manifests define slightly different HPA policies
(Section~\ref{sec:scaling-resource-allocation}). The production regression suite
is maintained separately rather than executed by our six repositories' CI
workflows, and a few frontend dependencies (\texttt{zod},
\texttt{next-auth}, \texttt{bcryptjs} in \texttt{ecomm-ui}) are declared but not
yet used.
\end{warningbox}

\section{Our Recommended Next Steps}\label{sec:recommended-actions}
Based on these findings, we recommend the following next steps for continuing our
work:
\begin{enumerate}[leftmargin=1.4em]
  \item \textbf{Integrate the production regression suite into CI} so the 95
        checks run automatically before deployment and prevent a recurrence of
        the payment-service file regression.
  \item \textbf{Complete the \texttt{/products}, \texttt{/products/[id]}, and
        \texttt{/categories} pages}; the fetch and rendering logic is already
        sketched out in code comments in each file.
  \item \textbf{Remove the plaintext secrets block} in \texttt{values.yaml} and
        rotate the associated credentials.
  \item \textbf{Restrict the currently-public network paths}: scope the Kubernetes
        API endpoint and worker SSH access to known IPs instead of
        \texttt{0.0.0.0/0}, and disable the direct NodePort path now that the
        Ingress Controller is in place.
  \item \textbf{Enable MongoDB authentication} and consider whether the five
        workloads should keep sharing one instance and one set of collections.
\end{enumerate}
