\chapter{Limitations and Future Improvements}\label{chap:limitations}

\begin{warningbox}[Current Limitations]
A few areas are still early or incomplete. Backend services and BFF routes do not
yet enforce authorization before mutating data (Section~\ref{sec:sec-app-auth}),
and regular users are not issued a session or token. Payment confirmation
currently relies on a client call rather than a Stripe webhook or session check
(Section~\ref{sec:sec-payments}). The \texttt{/products}, \texttt{/products/[id]},
and \texttt{/categories} pages are still placeholders
(Section~\ref{sec:frontend-completeness}), as is the admin dashboard's metrics
display. MongoDB runs without authentication or redundancy
(Section~\ref{sec:sec-data}), and \texttt{values.yaml} still carries an unused
plaintext secrets block worth cleaning up (Section~\ref{sec:sec-secrets}). The
Kubernetes API endpoint, worker SSH, and the NodePort range are currently
reachable from \texttt{0.0.0.0/0} (Section~\ref{sec:sec-network}), and the Helm
chart and raw Kubernetes manifests define slightly different HPA policies
(Section~\ref{sec:scaling-resource-allocation}). Automated tests are not yet part
of any of the six repositories, and a few frontend dependencies (\texttt{zod},
\texttt{next-auth}, \texttt{bcryptjs} in \texttt{ecomm-ui}) are declared but not
yet used.
\end{warningbox}

\section{Recommended Next Steps}\label{sec:recommended-actions}
\begin{enumerate}[leftmargin=1.4em]
  \item \textbf{Verify Stripe payments server-side} by replacing the
        client-triggered \texttt{/api/orders/confirm} call with a webhook that
        checks the event signature before marking an order paid.
  \item \textbf{Complete the \texttt{/products}, \texttt{/products/[id]}, and
        \texttt{/categories} pages}; the fetch and rendering logic is already
        sketched out in code comments in each file.
  \item \textbf{Remove the plaintext secrets block} in \texttt{values.yaml} and
        rotate the associated credentials.
  \item \textbf{Restrict the currently-public network paths}: scope the Kubernetes
        API endpoint and worker SSH access to known IPs instead of
        \texttt{0.0.0.0/0}, and disable the direct NodePort path now that the
        Ingress Controller is in place.
  \item \textbf{Enable MongoDB authentication} and consider whether the five
        workloads should keep sharing one instance and one set of collections.
\end{enumerate}

\section{Open Questions}\label{sec:open-questions}
\begin{itemize}[leftmargin=1.4em]
  \item whether the raw \texttt{kubernetes/} manifests should be retired now that
        ArgoCD manages the Helm chart, given the two already define different
        autoscaling policies;
  \item whether the shared MongoDB instance should be split per service before this
        architecture is reused beyond the internship context; and
  \item whether the OKE IAM dynamic group policy, currently commented out in
        \texttt{main.tf} for lack of tenancy access, should be revisited once
        broader access is available.
\end{itemize}
